# 7. Testing

## Running the tests

```powershell
dotnet test
```

No MySQL server is needed. The tests use an in-memory **SQLite** database, and everything else is the real production code: services, repositories, the audit interceptor, ASP.NET Identity, controllers, views and filters. A full run takes about 15 seconds.

## How the tests are built

* `Infrastructure/TestDatabase.cs` registers the real Application + Infrastructure services, then swaps MySQL for SQLite.
* `Infrastructure/GrsmsWebFactory.cs` starts the **whole website** in memory with the same swap, plus a test administrator, and puts emails, logs and keys in temporary folders.
* `HttpTestExtensions.PostFormAsync` behaves like a browser: it opens the form, reads the anti-forgery token and posts.
* The web tests switch off the automatic vacancy-closing job (`Vacancies:AutoClose = false`), because the in-memory test database must not be used by two threads at once. Closing is tested by calling it directly in `VacancyServiceTests`.

## What SQLite can't prove

> **Learned in Phase 11:** the Oracle MySQL provider could not read `DATE` columns into `DateOnly` ("Unable to cast DateTime to DateOnly"); SQLite could, so every test passed while Vacancies → All and the reports failed on MySQL. Fixed with a converter in `ApplicationDbContext.ConfigureConventions`. Open each new page against the Docker MySQL **with real rows in it**, not just an empty database.
>
> **Learned in Phase 6:** SQLite has no row-size limit, MySQL does (64 KB). A migration that passed every test failed on MySQL. Always apply each new migration to the Docker MySQL (`docker compose up -d --build`) before calling a phase done.

SQLite is not MySQL. The easiest real-MySQL check is the Docker set-up ([10 Running with Docker](10-docker.md)): `docker compose up -d --build` applies every migration to MySQL 8.4. This was first done on 4 November 2026 and all migrations applied cleanly. Before each release, also run the app once against a real MySQL server, to check:
* the SQL script applies cleanly (`database/*.sql`);
* duplicate checks ignore upper/lower case. MySQL's collation is case-insensitive, while SQLite's is case-sensitive, so the tests deliberately use exact-case duplicates.

## Adding tests for a new module

1. Service rules: copy the pattern in `OrganizationServiceTests` (`new TestDatabase()`, then one `NewScope()` per simulated request).
2. Screens: add a method to `WebTests` (or a new class with `IClassFixture<GrsmsWebFactory>`), sign in with `client.SignInAsync(...)` and drive forms with `PostFormAsync`.
